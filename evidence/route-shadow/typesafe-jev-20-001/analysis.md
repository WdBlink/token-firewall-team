# TypeSafe Jev 路由影子实验分析

## 结论

在本次 20 个去标识化模拟任务中，Jev 与当前 Token Firewall 路线一致 19/20（95%）。相对于冻结的协议专家参考：

- 当前路线：20/20；
- Jev 路线：19/20；
- Jev 错误下放到便宜模型：0 次；
- Jev 不必要升级到 Sol：1 次。

这支持继续把 Jev 作为非权威影子判断器，但不支持替换当前确定性路由策略。

## 唯一分歧：S03

任务要求按给定文案修改 README 的卖点、语言切换链接和 License badge，并运行 markdown link checker。当前路线与专家参考均选择 M3；Jev 的主分类同样以 1.0 置信度选择 `bounded_implementation`，但只给“Oracle 充分性”0.57，低于实验预先冻结的 0.70 门槛，因此最终升级到 Sol。

协议专家判断当前路线更合理：文案、文件范围和验证命令均明确，失败可逆，M3 交付后仍有确定性检查和独立复核。Jev 的选择是安全但偏保守的假阳性升级，会降低 Token 节省率，不会降低交付质量。

不应根据这一条结果事后把 0.70 调成 0.55。阈值应在更大的独立校准集上冻结后再验证。

## 调用成本与延迟

- Jev 版本：`jev-1.13.0`；
- 调用：20 次，每个任务一次；
- 输入 Token：15,220；
- 输出 Token：3,098；
- 按实验时官方文档的输入价 `$0.042 / 1M tokens` 估算：约 `$0.000639`；
- 平均延迟：507.7 ms；
- 中位延迟：497 ms；
- 最大延迟：629 ms。

## 严谨性边界

20 个任务来自近期 Codex 任务列表中反复出现的类别，但均为重新编写的去标识化模拟任务，不是原始会话导出，也没有执行实际任务。

“专家参考路线”是在 Jev 调用前按照当前 M3/Luna/Sol 协议冻结的政策标签，因此当前策略 20/20 并不是独立证据：当前路由和参考标签共享同一套规则。它只能帮助定位 Jev 与既定政策的分歧，不能证明当前路由在真实交付质量上优于 Jev。

本分析是协议专家判断，不是独立真人盲评。正式改变生产路由前，应让不了解 A/B 来源的人类评审者只看任务和两条候选路线，对分歧样本做盲评；还应扩大真实任务样本，分别统计“错误下放”和“不必要升级”。

## 决策

保持当前确定性路线为权威。Jev 继续运行在 shadow mode，保存原始概率和 Token 使用，但不影响 Agent 派发。下一阶段重点积累真实分歧样本，而不是根据这一轮 20 个模拟任务调整生产阈值。
