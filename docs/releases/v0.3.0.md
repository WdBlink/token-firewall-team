# v0.3.0 — Jev semantic eval

Token Firewall now requests TypeSafe Jev semantic scores before final review. The evaluator measures requirement coverage, semantic boundaries and evidence grounding, then attaches structured feedback to the existing independent review.

- Added `eval-typesafe` with a bounded, redacted packet and versioned rubric.
- First use prompts for `TYPESAFE_API_KEY`: hidden input in a terminal, actionable configuration guidance in Codex/noninteractive mode. Keys are not saved.
- Each attempt records its exact request, hash, response, model/usage when exposed, and latency; output files cannot be overwritten.
- Service failures and malformed answers escalate without granting acceptance. Existing Git/test, fresh verifier, Sol and human re-bet boundaries remain.
- Includes the previously local TypeSafe routing-shadow study and its full-input experiment report. Routing remains advisory.

Validation: 123 Runtime tests passed; Skill structure and CLI missing-key behavior checked. No live Jev API smoke test was run for this release because the executing environment had no TypeSafe credential. The integration has no calibrated reviewer-bypass threshold and establishes no new savings or quality-equivalence claim.

Install/update: `npx skills add WdBlink/token-firewall-team -g`.
